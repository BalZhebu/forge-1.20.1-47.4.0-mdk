# 2026-09-22 修复神考"生命值检查"（数值考核用的是裸值，不含外部加成）

## 症状
玩家面板上的最大生命值明明已经达标，点神考"检查"按钮却一直提示"考核条件未达成"。

## 根因
神考数值考核（`GodTaskType.ATTRIBUTE`）在 `network/client/C2SCheckTaskPacket` 里是：
```java
float currentVal = cap.getGodAttributeValue(target);   // target = "maxshengming"
```
而 `PlayerAttributeCapability.getGodAttributeValue()` 直接返回 capability 里的**裸字段**：
```java
case "maxshengming" -> this.maxshengming;
case "gongji" -> this.gongji;
...
```
这个裸值**只包含等级成长 / 神考奖励**，**不含**：
- 魂环加成（`HunhuanAttributeHelper.getWuhunBonus`）
- 魂骨加成（`PlayerAttributeCapability.getBoneOnlyStats`）
- 药水效果（`PotionAttribute`）
- 装备 / 套装加成（`ModArmorBaseItem`）

→ 面板上显示的是含全部加成的总额，检查却只看裸值，自然过不了。

## 面板到底显示什么（这次查清的）
`screen/attribute/AttributeScreen.renderFormattedAttributes`：
- **生命一栏 = `player.getMaxHealth()`**（第 137~138 行，`当前 / 最大` 都是原版属性值）
- 其余属性（攻击力/防御力/暴击率/暴击伤害/生命恢复/吸血/闪避/命中/物穿/抗暴）
  = `ModAttributeAPI.getXxx(player)`

配套事实：
- `KlMain.changeAttributesIO()` 用反射把 `Attributes.MAX_HEALTH` 的 **maxValue 字段改成
  `Float.MAX_VALUE`**，所以原版属性才能存下百万级血量（默认上限是 1024）。
- `PWPlayerTickEvent` 每 20 tick 把 `ModAttributeAPI.getMaxshengming(player)` 写进
  `Attributes.MAX_HEALTH` 的 baseValue → 所以
  `player.getMaxHealth()` = `ModAttributeAPI.getMaxshengming()` + 原版属性修正。

## 修复
1. 新增 `ModAttributeAPI.getPanelAttributeValue(Player, String attrKey)` ——
   **"面板显示什么就返回什么"** 的统一入口：
   - `maxshengming` → `player.getMaxHealth()`（面板"生命"那一栏）
   - 其余键 → 转发到本类已有的 `getGongji/getFangyu/getBaojilv/...` 聚合 getter
2. `C2SCheckTaskPacket` 的 `ATTRIBUTE` 分支改用它，并在未通过时**打印当前值 vs 要求值**
   （之前只报"未达考核要求"，根本看不出差多少 —— 这也是这次很难定位的原因之一）。
   配套加了 `attributeLabel(key)`（键 → 中文名）和 `formatAttrValue(float)`。
3. **删除** `PlayerAttributeCapability.getGodAttributeValue(String)` —— 唯一调用点已改，
   留着这个"返回裸值"的方法只会让同一个 bug 再犯一次。

## 经验（通用规则）
项目里同一个属性有**三种不同口径**，用错就会出现"面板达标却判定不通过"：

| 口径 | 取法 | 用途 |
|---|---|---|
| 裸值 | `cap.getXxx()` | 存档、等级成长、给奖励时累加 |
| 聚合值 | `ModAttributeAPI.getXxx(entity)` | 结算伤害/防御，含魂环/魂骨/药水/装备 |
| **面板值** | `ModAttributeAPI.getPanelAttributeValue(player, key)` | **一切"给玩家看的数值考核"** |

→ 凡是"按面板数值判定"的地方，一律走第 3 个，别再直接摸裸字段。
