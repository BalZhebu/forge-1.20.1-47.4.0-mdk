## 飞行速度档位系统（技能面板左侧面板底部 + ±按钮）

用户需求：技能面板左侧按键面板最下方有空白，新增两个按钮调节飞行速度，
速度越快 jingshenli 消耗越快。

### 改动
- 新增 `capability/playerattributes/FlySpeedTuning.java`：**唯一权威档位表**
  （MAX_LEVEL=4，共 5 档）。三张平行数组 SPEED_MULTIPLIER / COST_MULTIPLIER / LEVEL_NAMES，
  加档位只动这一处。BASE_SPEED=0.05F（= 原版创造飞行速度，所以档位 0 = 改动前手感）。
  - 速度倍率 1.0 / 1.8 / 2.8 / 4.2 / 6.0
  - 耗神倍率 1.0 / 1.6 / 2.4 / 3.4 / 4.5（涨得比速度快 → 高速不划算，玩家要权衡）
  - `applyFlyingSpeed(player, level)`：写 `Abilities#setFlyingSpeed`，
    **只在值变化 >1e-5 时才调 `onUpdateAbilities()`**（避免每 tick 发 abilities 包）。
- `PlayerAttributeCapability`：新增 `flySpeedLevel` 字段 + NBT 键 `FlySpeedLevel`
  （走已有 SPacketPlayerAttribute 同步链）+ getFlySpeedLevel / setFlySpeedLevel（clamp）
  / adjustFlySpeedLevel(delta)。
- 新增 `screen/attribute/skill/CPacketChangeFlySpeed.java`：C2S，只传 **相对增量 ±1**，
  服务端 clamp 后落存档 + 立即应用速度 + SynsAPI 回同步 + 发一条系统消息（显示档位与两个倍率）。
  已注册进 NetworkHandler。
- `PWPlayerTickEvent.updatePlayerFly`：开头调 `FlySpeedTuning.applyFlyingSpeed`；
  飞行扣精神力那行乘 `costMultiplier(level)`。
- `SkillWheelScreen`：左侧面板常量新增 FLY_TITLE_DY=172 / FLY_BTN_DY=182 /
  FLY_BTN_SIZE=14 / FLY_BTN_W=20（9 行按键占到 panelY+168，172~196 是空余区）；
  新增 drawFlySpeedControls（标题行「飞行 档位名」+「速×N 耗×N」+ 减号绿/加号橙 两个按钮
  + 中间档位进度条），drawFlyButton 画按钮（到顶/到底置灰），
  mouseClicked 里加 ± 命中判定（坐标与绘制同源，位置全由上面 4 个常量决定）。

### 项目事实
- 飞行速度走 `Abilities#setFlyingSpeed`，服务端改完必须 `player.onUpdateAbilities()`
  才会通过 ClientboundPlayerAbilitiesPacket 同步到客户端。
- 技能面板拿到的 cap 是**客户端侧 capability 副本**（由 SPacketPlayerAttribute 覆盖），
  所以 UI 读档位不需要额外包，回同步一次即可。

## 神速档位以上「高速撞墙爆炸」

用户需求：神速档位以上、**速度已提起来**时撞到方块引发爆炸；
威力默认按玩家攻击力、随速度比例增幅；35% 概率反伤自己，反伤致死时随机播 4 条吐槽。

### ⚠️ 顺手修掉的崩溃 BUG（用户自己加档位时引入）
`FlySpeedTuning.MAX_LEVEL` 被手写成 7，但三张表只有 7 个元素（索引 0~6）
→ 玩家把档位点到 7 时 `SPEED_MULTIPLIER[7]` **数组越界崩溃**。
已把 `MAX_LEVEL` 改成 `SPEED_MULTIPLIER.length - 1` **自动推导**，
三张表同步加项即可，以后不会再越界。

### 新增文件
- `capability/playerattributes/FlyCrashBlast.java`：爆炸玩法工具类。
  数值常量全在 FlySpeedTuning；死亡吐槽 4 条在 `DEATH_QUOTES`（`%s` 填玩家名）。
  伤害 = `ModAttributeAPI.getGongji × CRASH_DAMAGE_RATIO × crashSpeedFactor(档位,实际速度)`；
  范围伤害走 `playerAttack` 伤害源（能吃攻击力加成/暴击/飘字）+ 距离衰减 100%→40% + 击退；
  35% 概率 `playerAttack` 打自己 60% 伤害，致死则 `sendDeathQuote`。
  冷却存玩家 persistentData `FlyCrash_Cooldown`，由服务端每 tick 递减。
- `screen/attribute/skill/CPacketFlyCrash.java`：C2S，只带撞点 xyz + 撞前水平速度。
  服务端复核：仍在飞行 / 冷却已好 / 撞点距离 ≤3 格 / 速度 clamp 到 0~3（防刷包）。
- `screen/attribute/skill/FlyCrashDetector.java`：客户端 tick 检测并发包。

### ⭐ 关键项目事实（以后撞墙类判定都适用）
**原版移动包 `ServerboundMovePlayerPacket` 只带 位置/朝向/是否着地，不携带碰撞状态。**
服务端 `handleMovePlayer` 里虽然调了 `player.move(...)`，但 tick 事件里读
`horizontalCollision` 拿到的已是下一 tick 的值 → **服务端无法可靠判断"这一 tick 撞了墙"**。
必须**客户端检测**（`LocalPlayer.horizontalCollision` 每 tick 准确）再发包给服务端结算。

### 数值
- `CRASH_MIN_LEVEL = 4`（神速）；`CRASH_MIN_SPEED = 0.22` 格/tick（"速度已提起来"的门槛）
- `crashSpeedFactor`：实际速度/该档理论满速（`flyingSpeed × 8`）线性映射到 1.0~2.2
- `CRASH_DAMAGE_RATIO = 1.0`、`CRASH_RADIUS = 3.2`、`CRASH_SELF_DAMAGE_CHANCE = 0.35`、
  `CRASH_COOLDOWN_TICKS = 20`（客户端另有同值 localCooldown 兜底节流）

### 编译中踩的坑
- `PlayerTypes.SCRIT` 不存在（原版是 `CRIT`）
- **`Level#sendParticles` 不存在**，那是 `ServerLevel` 的方法 → 一律走项目自己的 `ParticleFx`

`gradlew.bat compileJava --offline` → BUILD SUCCESSFUL。

## 撞墙死亡消息改成自定义伤害源 + 反作用力提示移到物品栏上方

用户反馈：死亡播报方案不行，应该把撞击定义成**伤害源**（这样死亡消息由原版机制接管）；
撞击提示不要，只要反作用力提示；且提示不要走聊天栏，要画在物品栏上方。

### ⭐ 自定义伤害类型做法（1.20.1 数据驱动，项目内首次使用）
1. **4 个 json**：`src/main/resources/data/kunluncontinent/damage_type/fly_crash_1..4.json`
   ```json
   { "message_id": "kunluncontinent.fly_crash_1", "scaling": "never",
     "exhaustion": 0.1, "effects": "hurt", "death_message_type": "default" }
   ```
   字段来自 `DamageType` record：`message_id / scaling / exhaustion / effects / death_message_type`。
2. **语言键**：`death.attack.kunluncontinent.fly_crash_N`（**键名 = `death.attack.` + message_id**），
   写在 `ModZhCnLangProvider`（datagen 出到 `src/generated/.../lang/zh_cn.json`）。
3. **构造 DamageSource**（`FlyCrashDamageSource`）：
   `new DamageSource(level.registryAccess().registryOrThrow(Registries.DAMAGE_TYPE).getHolderOrThrow(key))`
   —— **`DamageSources` 是原版 final 类，无法扩展，自定义类型只能这样按 ResourceKey 现取**。
4. ⚠️ **不要传 causingEntity / directEntity** → `getLocalizedDeathMessage` 走"无归属"分支，
   用单参数格式（`death.attack.<msgId>`），文案完全自己控制，也不会被算成"自己杀自己"。
   想要 4 条随机就注册 4 个类型，命中时随机挑。
5. `death_message_type` 三档：`DEFAULT` / `FALL_VARIANTS`（可换"落地/撞墙"变体文案）/
   `INTENTIONAL_GAME_DESIGN`（不生成击杀播报）。想要多文案可组合 4 类型 × 3 档 = 12 条。

### 反作用力提示 → 物品栏上方 HUD
- `screen/client/FlyCrashHud.java`（新建，`RenderGuiEvent.Post`）：
  存活 50 tick，位置 `h - 22 - 12`（快捷栏正上方 12px）居中；前 6 tick 淡入、后 10 tick 淡出；
  带一层黑底 `fill` 保证亮背景下可读；`mc.screen != null`（打开任何界面）时不画。
- **S2C 包 `S2CFlyCrashHud`**（只带 float 伤害值，仅发本人）：
  ⚠️ **服务端不能直接调客户端静态方法**（专用服务器会崩），
  必须 `NetworkHandler.sendToClient` + 包 handle 里 `DistExecutor.unsafeRunWhenOn(Dist.CLIENT, ...)`。
- 已删除：FlyCrashBlast 里的 `sendDeathQuote()`、`DEATH_QUOTES` 数组、
  「魂爆」聊天提示、「反作用」聊天提示 —— 现在聊天栏完全安静。

## 修飞行档位进度条右侧残留空隙（显示 BUG）

现象：档位拉满后进度条最右端还有一小格没填。

根因：格宽用整除 `int segW = barW / segCount`。面板宽 130、两侧按钮与间距共 48
→ barW = 82；档位数 8 → `82/8 = 10`（整除丢掉 2），8 格只覆盖 80px，右侧空 2px。

修法：改用浮点边界平铺 `float segW = (float) barW / segCount`，
每段起点 `barX + Math.round(i * segW)`，且**最后一段直接画到 `barX + barW`**，
保证任何 barW / 格数组合都能填满（SkillWheelScreen#drawFlySpeedControls）。

### 通用教训
**画"分段进度条"一律用浮点边界 + 末段补到末端**，不要用整除格宽 ——
面板宽度几乎不可能被格数整除，整除必然在末端留 1~N 像素的空隙。

## 面板页签切换重构为注册表（新增面板从改 5 处 → 改 1 处）

用户需求：4 个面板（属性/魂骨/魂环/神考）各写了一份 40 行的页签代码，
新增面板要改 4 个 Screen + PacketSyncPage 的 if-else 链 + ModMenuTypes + ModItems，太多。

### 改动
- **新增 `screen/attribute/AttributeTabs.java`**（页签唯一权威定义）：
  - `record Tab(int id, String label, Supplier<ItemStack> icon, MenuProvider provider, BooleanSupplier visible)`
  - `ensureRegistered()` 幂等注册内置 4 个页签（PAGE_ATTRIBUTE/HUNGU/HUNHUAN/SHENKAO + PAGE_CONFIG 常量）
  - `buildTabs(host, currentPageId)`：自动遍历注册表生成整排页签（位置/间距/选中放大/上抬全在这算）
  - `buildConfigButton(host)`：右上角齿轮按钮（原先只有属性面板有）
  - 尺寸常量全部收进本类（NORMAL_SIZE=24 / SELECTED_SIZE=28 / SPACING=5 / OFFSET_Y=-26 …）
- **`PacketSyncPage` 去掉 if-else 链**：改为 `AttributeTabs.byId(id)` 查表 +
  `NetworkHooks.openScreen(player, tab.provider())`；配置页（PAGE_CONFIG）保留特殊匿名 MenuType。
  额外抽 `public static openPage(ServerPlayer, int)` 便于指令直接调用。
  **服务端也校验 `tab.isVisible()`**（未成神不许开神考面板）。
- 4 个 Screen 的 `init()` 各自删掉 ~40 行重复代码，各剩 1~2 行：
  `AttributeTabs.buildTabs(this, AttributeTabs.PAGE_XXX);`

### ⭐ 关键坑：protected 成员外部静态工具类访问不到
`leftPos / topPos / imageWidth / font / addRenderableWidget` 在 `Screen` /
`AbstractContainerScreen` 里全是 **protected**，静态工具类拿不到（编译 10 个错）。
解法：定义 `AttributeTabs.Host` 接口（leftPos()/topPos()/imageWidth()/font()/addWidget()），
各 Screen `implements AttributeTabs.Host` 并转发到自己的 protected 成员。
注意 `font()` 返回 `net.minecraft.client.gui.Font`（不是 int）。

### 效果
4 个 Screen 合计删掉约 150 行重复代码；**新增面板从"改 5 处"变成"改 1 处"**：
1. `AttributeTabs.ensureRegistered()` 里加一行 `tab(...)`
2. 新面板 Screen 的 init 调 `AttributeTabs.buildTabs(this, 新PAGE_XXX)`
（外加常规的 ModMenuTypes 注册 MenuType/MenuScreens、ModItems 加图标物品）

（第 1 次 10 错=protected 访问；第 2 次 1 错=instanceof 冗余；清理 import 后通过）
