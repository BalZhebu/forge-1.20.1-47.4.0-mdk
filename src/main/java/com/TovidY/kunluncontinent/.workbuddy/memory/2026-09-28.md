# 2026-09-28 分析技能释放的"魂环年限→强度"链路 + 修一个真 BUG

## 用户需求
"根据玩家吸收的魂环年限的强度来设定魂技释放的强度，看看有没有这个功能，若没有修复。"

## 结论：功能存在，链路完整；但有一个技能的年限加成被乘成 0

### 功能位置（链路）
1. **分档表**：`item/baseskillist/BaseSkillItem.getPowerMultiplier(long nianxian)`
   10年→1.0 / 百年→1.5 / 千年→2.5 / 万年→4 / 十万年→8 / 百万年→15 / 千万年→25 / 亿年→50。
   消耗同涨：`getCostMultiplier(int)`（1.0→3.5，log10 曲线）。
2. **伤害公式**：`finalDamage = ModAttributeAPI.getGongji(player) * getDamageMultiplier() * powerMultiplier`
   （`BaseSkillItem` line 35 / 101）——攻击力本身已含魂环加成（`getWuhunBonus`），所以年限是**双重**生效。
3. **三个释放入口都取年限**：
   - 瞬发：`screen/attribute/skill/CPacketReleaseSkill.executeRelease` line 58-62 → `handleRelease`
   - 吟唱：`event/server/PWPlayerTickEvent.handleSkillCasting` line 555-565
   - NPC：`entity/playernpc/NpcSoulSkillGoal.tryCastRandomSkill` line 60-71
4. **年限来源**：`cap.getMonsterCapabilityLists().get(wuhun).get(selectedSlot).getNianxian()`
   —— 第 N 魂技 ↔ 第 N 枚魂环（斗罗设定）。吸收时 `HunhuanWeakener.weaken` 走 NBT 拷贝，
   **不改 nianxian**；`HunhuanEntity.handleAbsorbed` line 151-155 用 `rings.size()` 定环序、
   `setWuhunSkill(wuhun, N-1, skill)` 放进对应槽位，与释放时的取法严格对齐。
5. 36 个技能类全部重写了 `executeEffect`（脚本扫过，无漏写）；用了年限倍率的技能都正确乘上。

### ⛔ 修掉的 BUG：八荒寂灭（八荒戟第九魂技）伤害恒为 0
- `item/baseskillist/bahuangji/nine/SkillBahuang9.java`
- 症状：`getDamageMultiplier()` 写成 **0**，而基类公式 `攻击 × 倍率 × 年限倍率`，
  → `finalDamage = 0` → line 35 `Bahuang9_Damage = finalDamage * 1.5f = 0`
  → `PWPlayerTickEvent` line 216/236 每次脉冲 `t.hurt(..., 0)` —— **完全不造成伤害，更不吃年限加成**。
- 修法：`getDamageMultiplier()` 改回 `1.0f`（每次脉冲 = 攻击 × 1.0 × 年限倍率 × 1.5，共 10 次，
  20 格 AOE / 70 秒 CD）。数值是平衡旋钮，注释里写清了公式。
- 排查方法：grep 所有 `getDamageMultiplier(){return 0` 的技能里谁还**消费 finalDamage** ——
  只有 Bahuang9 一个（其余是召唤/增益/真身，正确地不用 finalDamage）。

## 顺带发现的两处不一致（没改，留给用户定）
1. **5 个技能用固定基数而不是玩家攻击力**（仍随年限缩放，但不随攻击成长，后期会明显偏弱）：
   - `SkillLeijinhu1` line 91 `10.0f * 倍率 * powerMultiplier`
   - `SkillLeijinhu2` line 91 `4.0f * powerMultiplier`（连倍率都没乘）
   - `SkillPohun2` line 69 `10.0f * ...`
   - `SkillPanshijuyuan1` line 64 `15.0f * ...`
   - `SkillBahuang2` line 84 `12.0f * ...`
   要统一成 `playerGongji * 倍率 * powerMultiplier` 的话是 5 行改动，但会改平衡。
2. **阶梯式分档有悬崖**：99,999 年（×4）→ 100,000 年（×8）直接翻倍。
   想平滑可换成连续函数（如 `1 + log10(nianxian/10) * 0.7`）。
3. `SkillPanshijuyuan2`（石化皮肤）是纯自身 buff，固定 200 tick / 0 级，不吃年限。

## 校验
`gradlew.bat compileJava --offline` → BUILD SUCCESSFUL。

# 2026-09-28（第二件）全项目伤害路径审计：攻击力加成 / 暴击覆盖情况

## 用户疑问
"技能伤害 = 攻击力 × 技能倍率，且能吃暴击暴伤；项目里似乎很多攻击方式吃不到玩家攻击力加成，检查并修。"

## 结论：**没有吃不到的路径 —— 相反，技能的攻击力被算了两次**

### 攻击力加成的真正落点
`event/client/CombatEventHandler.onLivingHurt`（`LivingHurtEvent`，全局钩子，第 87 行）：
```java
float baseDamage = (gongji + event.getAmount()) * reductionFactor;   // gongji = ModAttributeAPI.getGongji(attacker)
```
任何"攻击者是 LivingEntity"的伤害都会被**加上攻击力**，再走 闪避→特效→**暴击**→吸血→飘字。
所以普通攻击 = 武器伤害 + 攻击力 ✓；**技能 = 攻击力 + (攻击×倍率×年限倍率)** ——
与用户描述的"首先根据玩家攻击力，然后加上技能倍率得出的伤害"逐字吻合，且暴击暴伤对整段伤害生效（第 107-116 行）。

### 43 处 `.hurt(` 全量审计（脚本扫描）
| 类别 | 伤害源 | 攻击加成 | 暴击 |
|---|---|---|---|
| 技能直伤 27 处 | `playerAttack/mobAttack(player)`、`indirectMagic(player,player)`、`explosion(player,player)` | ✓（双份） | ✓ |
| 延迟脉冲（Bahuang9/Liejinhu8/SuiXing/BuZhouQing/LieDi） | `playerAttack(player)` | ✓ | ✓ |
| 虚空云 VoidZone | `voidCloud.getOwner()` → `playerAttack`；owner 为 null 才 fallback `magic()` | ✓ | ✓ |
| 冰锥 IceShardEntity | 用 owner 的 `getGongji` + `thrown(this, owner)` | ✓ | ✓ |
| 燃烧 DOT ScorchingEffect | `getKillCredit()/getLastAttacker()` 归因回玩家 | ✓ | ✓ |
| 冰晶怪 IceCrystal（敌对生物，非召唤物） | 自己的 Mob 属性 | （合理） | ✓ |
| 天劫 PWPlayerTickEvent:806 | **故意绕过** LivingHurtEvent（注释写明），直接扣血 | 故意排除 | 故意排除 |
| 荆棘反伤 | 以受击者为攻击者 | 故意如此 | - |
| 斩杀（Leijinhu5/Pohun9） | `playerAttack` + Float.MAX_VALUE | - | - |
| NPC 技能 | finalDamage 已用 NPC 的 gongji 算好 | ✓ | ✓（FakePlayer 默认 5% 暴击） |

**没有需要修的"吃不到"路径。** 唯一一个真吃不到的是八荒寂灭（上一件已修：倍率 0 → 伤害恒 0）。

### 需要用户拍板的平衡点（没动）
技能伤害 = `攻击 × (1 + 倍率 × 年限倍率) × 减伤` —— 比纯"攻击×倍率"**多一整份攻击力**
（事件里加的那次）。若想去掉双重计算，需要给技能伤害打标（自定义 DamageSource 或 NBT 标记）
让 CombatEventHandler 对带标伤害跳过 `+ gongji`；这会让全技能伤害降 30%~50%，改前必须确认。

# 2026-09-28（第三件）第三种魂环开启方式推倒重做：旋绕归位 → 魂环升腾

## 用户反馈
"旋绕归位（从四周盘旋收束，转着定住）这种展开好丑，重新定义一个，做好看做霸气一些，
知道斗罗大陆吗？魂环就出自那里面。"

## 新样式：魂环升腾（斗罗式"从脚下升起"）
斗罗里魂环的标志出场就是**从脚下升起来**。设计：
- **起始点在地面之下**（世界高度约 -0.85 格）→ 环从地里钻出来的那一瞬被地面挡住，
  观感就是真的从地里长出来的；
- 前段（进度 62%）easeOutCubic 上冲，冲过环位到 **+1.15 格** 的峰值（那一下最霸气）；
- 后段 easeOutBack 缓缓落位，过冲让环在落位前先往上轻轻一挑再压回；
- 自转 `420 度 × (1-ease)`：出土时转得最快，落位时刚好停住；
- 尺寸 `0.40 + 0.60 × easeOutBack(t)`、淡入 `t × 5`；
- 神环（第 10 枚起）同样适用：restY 传 1.2（背部高度），起始点算出来也在地面之下。

## 实现改动
- `PWRenderPlayerEvent`：`ANIM_VORTEX` → `ANIM_ASCEND`（**配置值 2 不变**，老存档不用迁移）；
  `ANIM_STYLE_NAMES[2]` = "魂环升腾"。
- **openAnim 签名变了**：`ringRadius` 参数（只有旋绕用）删掉，换成 **restY（落定高度）** ——
  升腾要靠它算"地面之下"的起点。两个调用方分别传 `0.25+count*0.02`（魂环）和 `1.2`（神环）。
- `ConfigScreen` 里第 ③ 条的说明文字同步更新。

# 2026-09-28（第四件）变体魂技：一个物品图标对应多条魂技（兽武魂第一魂技池 ×5）

## 用户需求
"一个技能就代表一个物品图标，消耗资源太多；让指定魂技对应指定物品图标、一个图标对应多个魂技；
先给每种武魂的第一魂技加 4 个（加原先共 5 个），器武魂（破魂枪/八荒戟）第一魂技不加。"

## 关键事实：SkillLibrary 本来就支持多技能同槽位
`SkillLibrary.REGISTRY = Map<武魂, Map<环序, List<RegistryObject>>>`，
`getRandomSkill` 在池子里 `random.nextInt(pool.size())` —— 加技能只需往 List 里塞。
技能存档按**注册名**存（`ForgeRegistries.ITEMS.getKey` → `ITEMS.getValue` + `instanceof BaseSkillItem`），
所以新物品存档/读档零成本。

## 新增的基础设施（3 个类 + 1 个注册助手）
1. **`item/baseskillist/SkillEffect.java`**：`@FunctionalInterface`，
   `execute(ServerLevel, ServerPlayer, float powerMultiplier, float finalDamage)` ——
   LambdaSkillItem 已把类型收窄成服务端类型，lambda 里不用再判断。
2. **`item/baseskillist/SkillSpec.java`**：record `(descKey, baseCost, damageMultiplier, castTime, cooldownTicks, effect)`。
   ⚠️ **不放 nameKey** —— 物品名走默认 `item.<id>` 语言键（`add(Item, 名字)`），少一套概念。
3. **`item/baseskillist/LambdaSkillItem.java`**：extends BaseSkillItem，
   四个抽象 getter + getDescriptionKey 全部读 spec；`executeEffect` 里收窄类型后调 spec.effect()。
4. **`ModItems.skillVariant(id, iconSource, spec)`**：注册物品 + 记入 `SKILL_VARIANTS`
   （record `SkillVariantEntry(skill, iconSource)`）。

### 图标复用（零新增美术）
`ModItemModelsProvider` 新增循环：对 `SKILL_VARIANTS` 逐条
`withExistingParent(id, "item/generated").texture("layer0", modid:item/<iconSource 的注册名>)`
—— 项目里已有同款先例（`DEBUG_ITEM_BLOCK` 共用 `item/ceshi`）。

- 1B 金牙连斩（90/瞬发/6s，倍率 1.1）：最近目标连续三抓，每下 `dmg×0.4`

## 集成点（全部自动，无需改 UI/存档）
- 获得魂技：`HunhuanEntity.handleAbsorbed → SkillLibrary.getRandomSkill` 五选一（每个 20%）。
- 释放/UI/冷却/消耗：走 BaseSkillItem 既有链路；`SkillWheelScreen` 的名字/描述/冷却自动生效。
- 器武魂（破魂枪/八荒戟）第一魂技**未动**（用户要求）。
- ⚠️ 用户说的"凑齐 25%"按共 5 个算实际是**每个 20%**（等权随机），如要 25% 得每槽 4 条。

## 多段伤害的注意点
CombatEventHandler 会给**每次** hurt() 再加一份攻击力，所以多段技能天然比单段强
（三连斩 = 3×(gongji + 0.4×dmg)）。新技能的多段数值已按此调低。
